# 闪电分析显式复用当前前台 KataGo

闪电分析新增默认关闭的显式复用模式，只向开始任务时的当前前台、能力兼容的 KataGo 原子申请独占租约，不从其他已启动引擎中自动选择，也不在复用失败时静默启动专用引擎。选择这个边界，是因为多引擎配置没有稳定身份，隐式选择预加载或对局引擎会带来不可预测的状态干扰。

## Consequences

- 复用与本地进程、Remote Compute 或 Java SSH 等传输方式无关，但本次不扩展到非 KataGo 引擎。
- 界面状态检查只用于提前展示原因；真正的复用资格检查与租约设置必须在目标 `Leelaz` 内原子完成，并再次确认目标仍是当前前台引擎。
- 引擎对局准备或进行中、人机或自动对弈、Human SL 对局、`genmove`、ReadBoard GMA 自动落子、已有独占租约，以及引擎启动、识别、调参、重启、贡献或 benchmark 切换期间拒绝复用并说明具体原因。
- 普通前台持续思考不属于忙碌状态；取得租约后暂停思考，结束时恢复棋盘状态，并仅在目标仍然有效且此前正在思考时恢复思考。
- 对局、`genmove`、ReadBoard GMA 和其他独占工作的启动入口也必须检查同一租约，防止它们在闪电分析取得引擎后并发启动。
- 前台分析租约和引擎模式保留由同一个引擎仲裁边界管理，但保持两个强类型概念：前者独占 GTP 输出流，后者只阻止冲突模式。公共入口只申请一次，已持有保留的内部路径不得嵌套申请，避免自我阻塞和锁顺序反转。
- ReadBoard GMA 的模式保留覆盖临时参数设置、落子请求、棋盘恢复和参数恢复确认；只有全部成功响应后才释放。任何恢复错误或超时都把引擎标记为状态未恢复，并在用户切换或重启前拒绝新的引擎操作。
- Remote Compute 的 WebSocket 适配器必须保留 GTP 持续响应边界：`kata-analyze` 的 stop 回执和底层 JSON 分析终态分别跟踪，只有原查询终态才能结束分析响应；传输关闭、远端错误或畸形响应必须显式终止上层会话。
- 复用模式不读取或覆盖专用闪电分析命令，不执行专用引擎的预加载或分析后关闭策略；启用复用时关闭已经空闲预加载的专用引擎。
- 复用关闭时，专用闪电分析命令以用户保存内容为准，不再隐藏地跟随当前前台引擎。命令缺失时先提示并打开设置，有效保存后续接原分析请求。
- 用户保存过的专用命令不得被自动设置、权重切换或路径修复覆盖；只有确认由旧版本自动生成且未经用户保存的命令可以自动迁移。
- `-quit-without-waiting` 只影响专用 KataGo analysis 进程关闭 stdin 时是否等待未完成任务，不是 analysis 模式必需参数，也不适用于复用 GTP 引擎。
- 例外：`cd11fe80`（2026-08-14）起，自动棋谱快析在以下情况会隐式复用当前前台 KataGo，不需要用户开启复用开关：前台是远程算力且没有请求轻量快析模型；或者前台是内置 NVIDIA 引擎，并且它是 TensorRT 版，或者没有请求轻量快析模型。复用对象仍然只限当前前台引擎；用户手动发起的闪电分析仍按显式开关处理。这个例外的原因没有记录（见 `AnalysisEngine.shouldAutomaticallyReusePrimaryForeground`）。
